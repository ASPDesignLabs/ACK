# ACK Voice Studio: what an IT department needs to know, allow and check

**For:** a system administrator, IT support or a security reviewer who has been asked to approve this on a computer.
**From:** whoever handed you this page. They want to make a personal synthetic voice from their own recordings, for a speech-generating
phone app (ACK, an AAC app), and the set-up has to reach a few internet addresses that a careful network policy may block.
**This page is meant to be read in ten minutes and answered with a yes, a no, or a list of changes.**

> **Status, said plainly.** Today ACK Voice Studio is a set of terminal programs with a window with pages for projects, recordings, training rounds, hearing a voice, the voice file, backup, freeing up space, checking the tool, updates and problem reports (section 7); a page for getting a starting voice is not built yet, and this page describes
> what the terminal programs do. It has been run on **Ubuntu 22.04 and Ubuntu 24.04 under WSL2 (Windows), with an NVIDIA RTX 4060 (8 GB)**, by
> the developer. It has **not** yet been run on native Ubuntu by anyone, not on a managed or locked-down network, and not by a second person.
> Where this page says a thing was *tested*, it was; where it says *by design*, nobody has measured it. Section 11 lists both.

## 1. What it is, in thirty seconds

* The person records their own voice on their phone with the ACK app. The recordings go to the computer on a cable or USB drive.
* This program turns the recordings into a *voice file* by training a small neural network **on the computer's own graphics card**.
  Nothing is uploaded to train it. The result is one `.zip` file that goes back to the phone the same way.
* It is open source (GPL-3.0-or-later): `https://github.com/ASPDesignLabs/ACK`, folder `tools/voice_studio`.

## 2. The short version: what to approve

Tick what you will allow. Sections 3 to 9 give the detail for each line.

- [ ] **The computer** (section 3): Ubuntu 22.04 or 24.04 (WSL2 on Windows is what was tested), the system Python 3.10 to 3.12, an NVIDIA graphics
  card with 8 GB or more and its normal driver, and about **63 GiB** of free disk (25 GiB is the bare minimum).
- [ ] **One-time administrator rights** (section 4) to install seven Ubuntu packages.
- [ ] **Outbound HTTPS, port 443 only** (section 5) to the hosts in the table, during set-up. *Or* use one of the offline routes in section 6.
- [ ] **No inbound ports** from Voice Studio itself (section 7). One *separate, optional* tool (Freeform Studio) can open a port on the local network, and
  you may leave that unapproved.
- [ ] **Where it writes and what runs** (section 7): one folder in the user's home, long-running programs started by the user, no services.
- [ ] **Data handling** (section 9): recordings, transcripts and the trained voice stay on the computer.
- [ ] **Licences** (section 10): someone who handles licensing should read it before the voice is used beyond the person's own phone.

## 3. The computer

| Needed | Detail |
|---|---|
| Operating system | Ubuntu 22.04 or 24.04. Tested under **WSL2** with the Windows NVIDIA driver (no Linux driver is installed inside Ubuntu). |
| Python | The Ubuntu system Python: **3.10, 3.11 or 3.12**. The tool refuses anything older, and its locked programs are verified up to 3.12. |

| Disk | **About 63 GiB free** for two people's projects and both starting voices (the tool's own figure); **25 GiB** is the bare minimum it will start with. A single training round keeps about 4.8 GB of checkpoints. The tool shows these numbers and refuses to start without room. |
| Administrator rights | **Once**, for section 4. Afterwards everything runs as the ordinary user. |

## 4. One-time installation with administrator rights

The set-up script (`tools/voice_studio/setup.sh`) looks first, lists what is missing, asks once, and then runs exactly this (installing only the packages that are not already present) and nothing else:

```text
sudo apt-get update
sudo apt-get install -y python3-venv python3-dev build-essential git ffmpeg python3-gi gir1.2-gtk-4.0
```

| Package | Why |
|---|---|
| `python3-venv`, `python3-dev`, `build-essential` | Keep the tool's Python programs separate from the system's, and build **one** tiny part locally (a one-kilobyte C source file shipped with the tool and checked by SHA-256; this is the only place anything is compiled). |
| `git` | To fetch the tool itself and its updates. |
| `ffmpeg` | Reads and converts the audio recordings. |
| `python3-gi`, `gir1.2-gtk-4.0` | For the window (`python3 -m voice_studio.window`, section 7). Not needed to build or train. |

On a freshly installed Ubuntu 24.04 this pulled **206 new packages and upgraded 15** (233 MB to download, 552 MB on disk), mostly `ffmpeg` and
the GTK toolkit with their dependencies. The script runs `--check` (changes nothing) and `--dry-run` (prints the commands) first if you ask it to.

**On Windows: `install.ps1`.** Someone with only PowerShell can run one line (`irm <address of install.ps1> | iex`, or save the file, read it and run it with `powershell -ExecutionPolicy Bypass -File`, which changes no setting) and end with the window open. The script is plain text of about three hundred lines in `tools/voice_studio/install.ps1`, written for Windows PowerShell 5.1 as well as 7. What it does:

* **Reads** the Windows build number, whether virtualization is on (`Win32_ComputerSystem`, `Win32_Processor`), the Nvidia driver through `nvidia-smi.exe` if there is one, and the free room on the system drive. It writes nothing on Windows.
* **Runs `wsl.exe`** to list distributions (`wsl.exe -l -v`), to read the Ubuntu user id (`wsl.exe -d <name> --exec id -u`, to make sure Ubuntu has a user and the tool is never put in root's home), and, only if there is no Ubuntu 22.04 or 24.04 and only after a yes, `wsl.exe --install -d Ubuntu-24.04`. That one needs PowerShell opened as administrator and a restart; the script does not elevate itself, it says how to open an administrator window.
* **Starts the Ubuntu part** with `wsl.exe -d <name> --cd ~ --exec bash -c <one command>`: fetch `get.sh` with `curl` (or `wget`) from `raw.githubusercontent.com`, then run it with `--no-window`. From there it is section 4 and the rest of this page, in the same console: `wsl.exe` is started on the person's own PowerShell console (so Ubuntu's password prompt and questions appear and can be answered there), not with its output captured.
* **Opens the window** as a second `wsl.exe` session that it stays attached to until the window is closed (`wsl.exe -d <name> --cd ~ --exec bash -c 'PYTHONPATH=$HOME/ack-tools/tools exec /usr/bin/python3 -m voice_studio.window'`). WSL stops an Ubuntu that has no session open from Windows about a minute after the last one ends; a session that stays attached keeps the window up. The PowerShell window is busy until the Voice Studio window is closed.
* **Does not**: ask for or see a password, change the PowerShell execution policy, touch the registry, add a scheduled task or service, install anything on Windows beyond what `wsl --install` itself installs, or make a web request of its own. A test reads the file and fails if it does.
* **Release.** The script and `get.sh` fetch the release named in `ACK_VOICE_TAG` (`-Ref`), `main` by default. To pin a reviewed release, set that name; both scripts use it for the fetch.
* **Tested** with PowerShell on Linux, with stand-ins for `wsl.exe`, for the questions and for the facts about the computer, covering every branch; **not yet run on a clean Windows**.

## 5. Network: what is contacted, when and why

All of it is **HTTPS on port 443**, outbound, during set-up. By design nothing is contacted by timer or in the background, and only one module of the tool (`core/fetch.py`) may use the network at all (a test enforces that). The tool shows every download, with its
address, size and checksum, and asks **before** it starts; the person's yes is saved in `~/ack-voice-studio/state/consent.json`.

| Host | What for | Size | When |
|---|---|---|---|
| `pypi.org` | The Python package index (pip looks packages up here) | small | set-up |
| `files.pythonhosted.org` | The Python packages themselves: the training programs (about 3.2 GB, 91 packages) and the studio programs (about 145 MB, 46 packages) | about 3.3 GB | set-up |
| `huggingface.co` | File listings and downloads of the listening model and the starting voices (table in section 8) | 4 small files, one 483 MB file, two 846 MB files | set-up; a starting voice when the person chooses it |
| `*.hf.co` (observed: `us.aws.cdn.hf.co`) | The large files are served from here after a redirect from `huggingface.co` | included above | same |
| `archive.ubuntu.com`, `security.ubuntu.com` (or the organisation's own Ubuntu mirror) | The Ubuntu packages in section 4 | about 233 MB | once, with administrator rights |
| `github.com` | To fetch the tool itself (`git clone`), and a newer release of it | about 7 MB for the tool; a release is usually under 100 MB (not yet measured) | install; a release only when someone runs `python3 -m voice_studio.update` and types yes (or runs `git pull`) |
| `raw.githubusercontent.com` | The two small setup scripts, install.ps1 (Windows) and get.sh (Ubuntu), fetched when someone runs the one-line install command | a few kilobytes | install |
| Microsoft's servers (reached by the Windows program wsl.exe, never by the tool) | WSL and the Ubuntu image, only on a Windows that does not have them yet | the Ubuntu image | once, on Windows |

**About the redirect host.** Hugging Face decides where the large files are served from, and that can differ by region and over time. `us.aws.cdn.hf.co` is
what was observed from one place on 2026-10-11. If a large download is blocked, the tool's error names what failed; you can see where an address
leads with `curl -sI "<address>"` and reading the `location:` line. Allowing `huggingface.co` and `*.hf.co` is the simple rule.

**Addresses that are shown but never contacted.** Before a starting voice is fetched, the tool will show the web addresses of the pages that state its licence (section 10), so the person can read them. It **never opens
those pages**; nothing in the tool can: its only network code downloads the pinned files in section 8. They need no firewall rule for the tool to work.

**What it does not contact.** No telemetry, no analytics, no automatic update check (the only way the tool asks about a newer release is `python3 -m voice_studio.update`, which asks first: section 7), no cloud service, no account. Programs the tool starts for training and for
listening to recordings are started with `HF_HUB_OFFLINE=1`, `HF_HUB_DISABLE_TELEMETRY=1`, `DO_NOT_TRACK=1` and `TRANSFORMERS_OFFLINE=1`, and the one thing in the trainer
that would have fetched code from the internet at run time (an optional quality scorer) is switched off. *Tested:* a run with the scorer off logged **zero** lines about it.
*By design, not measured:* that a training round succeeds with the network cut off completely.

**Proxies and inspection.** The tool runs the ordinary `pip` and Python's standard downloader, so `HTTPS_PROXY`, `pip.conf` and the system certificate store apply as
they do for any other Python program. A TLS-inspecting proxy needs its certificate authority in the system store. *Not tested here.*

**If the connection drops** mid-download, the tool waits (5, 10, 20, 30, then 60 seconds, for up to 30 minutes) and carries on by itself.

## 6. If outbound access cannot be opened: offline routes

1. **Hand over the listening-model files.** Download the four files in section 8 on an approved machine, check their SHA-256, and put them in
   `~/ack-voice-studio/tool/downloads/models/speech-small-en/` with exactly those names. The tool checks size and SHA-256 of a file that is already there
   and **skips the download** when it is right. A copy of the same four files in the Hugging Face folder (`$HF_HUB_CACHE`, else `$HF_HOME/hub`, else `~/.cache/huggingface/hub`, in `models--Systran--faster-whisper-small.en/snapshots/<revision>/`, as Freeform Studio's own `models fetch small.en` leaves it) is used too, read-only, when every file has exactly the pinned size and SHA-256; nothing is copied or moved. Without outbound access to do it by hand, `python3 -m voice_studio.recordings model` is the one command that downloads these four files itself (it names the site and the size and asks first). A starting voice is fetched by the person with `python3 -m voice_studio.voices get <voice>` into `~/ack-voice-studio/tool/downloads/voices/<voice>/`, and the same rule applies: a file placed there with the exact pinned name, size and checksum is used with no download. The person still has to read and acknowledge where the voice comes from (section 10).
2. **An internal Python mirror.** The tool installs with `pip install --require-hashes --only-binary=:all: --no-deps`, so every wheel is pinned by SHA-256 in
   `tools/voice_studio/data/locks/training.lock.txt` and `studio.lock.txt`. A mirror must carry those exact files. Point pip at it with its usual
   settings (`PIP_INDEX_URL` or `pip.conf`). *Not tested here.*
3. **Ubuntu packages from the organisation's own repository,** as for any other machine.

## 7. What gets installed, where, and what runs

* **Everything is under one folder in the user's home:** `~/ack-voice-studio/`: `projects/` (one folder per person), `tool/` (the two Python environments, about 6.6 GiB, and the downloaded
  files, about 2.2 GB once the listening model and both voices are fetched), `state/` (small records), `backups/`. Nothing is installed system-wide except the packages in section 4.
* **pip also keeps its normal download cache** in `~/.cache/pip` (roughly the size of the downloads). It can be deleted at any time.
* **Long-running programs.** Training and listening to recordings run as the user's own ordinary Python processes, for minutes to hours, using the graphics
  card. They keep running if the terminal is closed, by design, and the tool can stop them on request. **There are no services, daemons, cron jobs or start-up items.**
* **Training rounds write a lot, in one place.** Each round keeps about 4.8 GB of saved files (six of about 807 MiB) under the project's `rounds/run/` folder, and a small working folder under the project's scratch folder (`scratch/caches/`, which the tool never reuses between rounds). The tool never deletes, moves or renames any of it by itself. A person who runs many rounds will see the disk fill: `python3 -m voice_studio.rounds keep` lists what is kept for sure and what is spare, with sizes, and removes nothing; `python3 -m voice_studio.rounds free` lists what could be freed (spare saved files and the working files of rounds that have ended, never recordings, notes, backups, voice files or the starting voices) and, only when told which rounds, shows exactly what it will remove and asks first. What it removes cannot be brought back. `python3 -m voice_studio.voicefile make` writes one new folder under the project's `exports` (about 1 GB at most, usually far less) holding the voice, its settings file, the original before it was prepared and the zip file for the phone; it changes and removes nothing that was there. A small record of the rounds, `rounds/rounds.json`, is the only file the tool itself keeps about them.
* **Voice data can be brought in by hand, and a project can be deleted.** `python3 -m voice_studio.recordings import SOURCE --kind K` (also the window's Recordings page) brings in an ACK package, or a folder (or a `.zip` of one) of audio files: each with a text file, with one table of sentences, or alone. The kind is always chosen by the person. It reads the chosen place and never changes, moves or deletes anything in it; everything it adds is copied into the project's own `recordings/` folder (a package's checked copy under `incoming/`, a zip of files unpacked there, only the audio and text names it should, never a link or a name that climbs out of the folder). It shows what it found and the room it needs, and writes nothing until the person says yes. A file is recognised by its content, so bringing the same folder in twice adds nothing; a file that cannot be read is named and left out. The same flows never use the network, and the window's file chooser only returns a path. `python3 -m voice_studio.recordings finish` starts the listening as one detached job on the processor (not the graphics card) and refuses a second one while it runs; `set` writes a training set only into a new folder under the project's scratch folder, after asking. `python3 -m voice_studio.projects delete` removes one project's own folder **after two questions** (`--yes` answers only the first), lists what goes first and says whether the project has been backed up (and where the last backup is), refuses while a task of that project is running, and removes a scratch place the person chose elsewhere only if its marker names that very project; `archive` only hides a project and removes nothing.
* **A disk guard runs inside the job's own supervisor.** A training round is started with a free-space floor for the drive it writes to; the small detached supervisor program looks every five seconds and, if the free space falls below the floor, asks the training program to stop the way Ctrl+C does (it saves what it can), and records that the reason was the disk. It only reads free space; it deletes nothing. A drive that cannot be read is not judged. Before a round starts the tool also reads the graphics card's memory use with `nvidia-smi` and refuses a round that would not fit.
* **Hearing a finished voice before it goes to the phone (new; built and tested in a build sandbox only, with no speaker).** `python3 -m voice_studio.voicefile listen` shows what it will do and asks first. It runs one short program with the studio programs' own Python, `python3 -m voice_studio.listen_runner JOB.json`, which loads the voice and writes three small sound files into a new folder under the project's own `listening` folder (one folder for each round or voice file, one inside for each time). That program opens no network connection and prints no sentence, and the speech engine is the one the phone app uses, sherpa-onnx 1.13.8, installed from the package site with the other studio programs (it has the GPL-3.0-or-later espeak-ng compiled in: see `THIRD_PARTY_NOTICES.md`). The tool then **plays the files by starting an audio player** and keeps the first one that works: on a desktop Ubuntu, `pw-play`, `paplay`, `ffplay`, `aplay`; under WSL, `ffplay`, `paplay`, Windows' own player, then `aplay`. Windows' own player is `powershell.exe -NoLogo -NoProfile -NonInteractive -EncodedCommand ...` with a command that only creates a `System.Media.SoundPlayer` for the file's Windows path (from `wslpath -w`) and calls `PlaySync()`. A test reads the player list and that command from the code. Nothing is recorded, installed or left running, and the sound files are small and are removed only by the tool's *Free up space* page or command, when asked. Two optional additions run only when asked for or when the model is already on the computer. **Writing down what was heard:** a second short program with the studio programs' own Python, `python3 -m voice_studio.hear_runner JOB.json`, loads the listening model from its folder only (the same files as in section 8; no download happens here, and `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, `HF_HUB_DISABLE_TELEMETRY=1` and `DO_NOT_TRACK=1` are set by the program itself whatever the computer says) and prints what it hears in the sound files; it is told no sentence, and it uses about as much memory and processor time as listening to a recording. **`--round`:** `python3 -m voice_studio.voicefile listen --round chosen` makes the voice from a round's saved point in the new listening folder with the same export and patch programs that `make` runs (minutes of processor time and up to about 664 MB of disk), then asks before removing that large copy; it makes no zip file and starts no new kind of program. Neither addition opens a network connection.
* **Backing up a project (new; built and tested in a build sandbox only).** `python3 -m voice_studio.backup now` shows what it will do and asks first, then writes **one plain, uncompressed `.tar` file** and a small `.tar.json` note beside it, both readable by the person alone, into a folder the person names, which must be outside every project (the tool's own `~/ack-voice-studio/backups` if none is named). It holds the part of one project that cannot be made again: the project record and consent note, the recordings (the raw audio, the notes and the person's edits, not the decoded copies), the recording packages from the phone, the record of training rounds and each round's settings file, the saved points that are kept, and the finished voice zip files. It leaves out working files and training sets, the test sounds, older saved points, the trainer's logs, the tool's programs, the starting voices and earlier backups. The file is written under a `.partial` name, **read back in full** against a list of every file's size and SHA-256 checksum, and only then given its name; a backup that does not read back is removed. It is a new file every time: the tool **never replaces, prunes or removes a backup**. `python3 -m voice_studio.backup restore` only adds what is missing and never overwrites a file (a file that differs is left as it is and listed), checks every name in the archive against the few shapes a backup holds before it writes, and refuses while a task of that project is running. `verify` and `list` only read. A one-line reminder (`has not been backed up yet`, or `has changed since the last backup`) is printed before a round is started and after recordings are brought in; it writes nothing and stops nothing. The only thing the tool remembers about backups is `state/backups.json` (when each project was last backed up, where, and a fingerprint of its files then; owner-only, per computer, never inside a backup). None of this uses the network (a test reads the source for it).
* **Checking the tool and refreshing it (new; built and tested in a build sandbox only).** `python3 -m voice_studio.refresh check` looks at each set of programs (it reads its record and runs its own self-test again, offline, writing nothing, not even to its log), at the files that were downloaded (byte for byte against the sizes and SHA-256 checksums in the registry) and at four small notes the tool keeps; it changes nothing and reaches no network. `repair` mends only what `check` found, after showing it and asking: it hands an unfinished set of programs back to the same builder (which shows what it will download and asks again), fetches a damaged download again (only if the person's saved agreement covers that exact file, and the new file replaces the old one only after it has been checked, so a failed fetch leaves what was there), and sets aside, never deletes, a note that cannot be read. `rebuild` builds a **second whole copy** of a set of programs beside the one in use, by the same builder and the same questions as the first setup, with a generation number (`state/environments.json`) in the folder's name; the number is raised only after the new copy has passed its self-test, so the old copy stays in use until then and a rebuild that fails costs only disk space. The old copy is then offered for removal with a typed yes (`--yes` does not answer it); `older --remove` removes only folders that carry this tool's record and whose name matches it, never the one in use, never one that is being built, never while a task is running, and only the list that was shown. None of it touches a project, a recording, a round, a finished voice or a backup. Its downloads are the first setup's (section 5), and only after a yes.
* **Removing the programs and downloads (new; built and tested in a build sandbox only).** `python3 -m voice_studio.uninstall show` lists what an uninstall would remove and what it keeps, and changes nothing; `python3 -m voice_studio.uninstall remove` shows the same list, asks once (a typed yes, or `--yes`; nobody to ask means nothing is done) and removes only what was shown. What it removes is only what the tool made and can make again: the sets of programs in `tool/environments` (a folder that carries this tool's own record and is not being built) and the downloaded files in `tool/downloads`. It never removes a project, a recording, a round, a finished voice, a backup (`backups/`), the starting voices (`tool/downloads/voices`, a kept copy that may not be downloadable again), or the small notes in `state/`; a list of the tool's own places (`core/areas.py`) decides what is the tool's, and a test fails if a removal could reach a place it calls precious. It refuses while any task is running, removes a link as a link and never follows it, and removes nothing if what is there is no longer what it showed. It cannot remove the folder it runs from or the menu entry, so it prints the command for each (the window's own `--remove-launcher`, which also handles the Windows Start menu, and an `rm -r` the person types). It contacts no network.
* **Moving a project's scratch (new; built and tested in a build sandbox only).** Scratch is where a project keeps its training sets and each round's working files; it is inside the project by default, or in a folder on another drive that the person chose when the project was made. `python3 -m voice_studio.scratch show` says where it is and whether it can be used, and changes nothing; `python3 -m voice_studio.scratch move --to FOLDER` (or `--default`, to move it back inside the project) checks the new place with the same rules as a new project (a folder that looks cloud-synchronised, a network drive, a memory disk, a read-only drive, another project's folder and the project's own folders are refused), shows what it will do, asks once, copies every file into the new place (each file is written under another name, read back and compared, and only then put in place), checks the whole copy against the old place again, and **only then** changes the project's record to point at the new place (`project.json` is replaced atomically and the old one kept as `project.json.previous`). Until that step the project still uses the old place, so a failed or stopped move costs only disk space and the same command carries on, skipping files that are already there and identical. The old place is never touched by the move: a second question, a typed yes that `--yes` does not answer, offers to remove it, and removes only a folder this tool made (the folder in a chosen place whose marker file names this project, or what is inside the project's own scratch folder). It refuses while any task for the project is running (checked again just before the switch), writes the copy readable by the person only, never follows a link, and contacts no network. The training sets in scratch cannot yet be rebuilt by this tool, which is why the copy is checked file by file.
* **Updating the tool (new; built and tested in a build sandbox only, never against github.com).** `python3 -m voice_studio.update check` asks `github.com` which releases of ACK Voice Studio exist, and `python3 -m voice_studio.update get RELEASE` fetches one into a **new folder** beside the copy that is running. A release is a git tag whose name begins with `voice-studio-` (set in the registry, `data/sources.json`, as `tag_prefix`); the repository also holds the phone app's tags (`v1.0-beta.1` and the rest), which are left out of the list and cannot be fetched by this command, and the name shown is the tag without the prefix. It is the one command after set-up that contacts the internet at the person's request without being one of the downloads in section 8, so it works the same way: it says first what it will ask `github.com`, that the request carries the computer's address and the name of the program asking and nothing the person recorded, typed or made, and the exact commands, then asks once (a typed yes, or `--yes`; nobody to ask means nothing is contacted). The commands are `git ls-remote --tags https://github.com/ASPDesignLabs/ACK.git` and, for `get`, `git clone --depth 1 --branch voice-studio-RELEASE https://github.com/ASPDesignLabs/ACK.git NEWFOLDER`. They are started through the download module (`core/fetch.py`, the only module that may use the network) with `GIT_TERMINAL_PROMPT=0`, so git never waits for a password, and with an agreement that names exactly those two steps for that run only: nothing is saved and nothing is ever checked in the background. The address is in the registry (`data/sources.json`) and a test fails unless it is an `https` address without credentials on an allowed host. A release name must be letters, numbers, dots, dashes and underscores (at most 64) and must be one the list returned. After the fetch the copy is checked: it holds the commit the release was listed with (read from its `.git` files, with no program started for that) and it is a copy of this tool; if either is not so, the folder this program made is removed again and nothing else is. A folder that already exists is never used and never removed. It then compares the new copy with the one that is running by area (the lists of programs, what can be downloaded, the words on screen, the recording tool, the tool's own program files and the guides) and says which differ; it reads files only. It **cannot replace the folder it is running from**, so it prints the commands for trying the new copy and for using it under the usual name (two `mv` commands) and does not run them. The guided setup then builds only the programs whose lists changed, beside the old ones, and asks first (section 5). It touches no project, recording, round, finished voice or backup, and it needs `git` (section 4). **No tag beginning with `voice-studio-` exists yet**, so against the real address `check` says there is nothing to fetch (the repository's own tags are the phone app's, and are not listed).
* **The problem report (new; built and tested in a build sandbox only).** `python3 -m voice_studio.report show` builds a text report for a helper and prints all of it; `python3 -m voice_studio.report save --to FILE` prints the same text, asks once (a typed yes, or `--yes`; nobody to ask means nothing is written) and writes exactly that text to the one file named. It holds the tool's version and Python's, the operating system, the graphics card and the memory, the checks the first look makes, the free space of the data folder, the problem the person names (with the tool's three sentences for it) and, with `--job`, how a task ended; with `--include-log` as well, the last 60 lines of that task's log, each cut to 300 characters, with a warning that they may contain words from recordings. It has **no place for a recording, a transcript or a phrase** (a test pins the fields of its input), and names and folders are replaced by markers in one pass: the login name, the home and data folders, the computer's name, every Windows profile, every project's name and folder name and the name of whoever agreed to a project, email and network addresses, access tokens and drive labels. It **contacts no network and starts no program**, makes no folder, never replaces a file unless `--replace` is given, writes the file readable by its owner only, reads it back and removes it if it differs, and removes a half-written file of its own on a failure or Ctrl+C. It warns, and does not refuse, when the folder looks cloud-synchronised. A command that fails after it began (exit 1) ends with two lines pointing at it; a command that was declined or could not ask gets none, and the line names the one problem that command told the person about when there was exactly one. *Stated limits:* a name of one letter is not hidden, a name of four letters or fewer is hidden only as a whole word, and the redactor knows only the names it is given, which is why the log is opt-in.
* **Ports.** By design the programs the tool starts open no listening port (single-card training uses local pipes only). *Not measured with a port scanner.*
* **The window (tried so far on one computer, with WSLg).** `/usr/bin/python3 -m voice_studio.window` opens one window with eleven pages: Projects, Recordings (bringing voice data in, listening, training sets), Training rounds, Hear the voice, Voice file, Backup, Free up space, Check the tool, Updates, Problem report and Display. It needs the system Python (the one Ubuntu's `python3-gi` belongs to; a virtual environment's Python cannot see GTK) and a desktop (on WSL, graphical Linux programs). It is only a front for the same commands the terminal runs: every change is shown and asked about first, and the window writes a file of its own only if the person says yes to a question that names the file: `state/window.json` in the tool's folder, which holds the colour theme, the accent colour, the text size and the size of the window, owner-only, and nothing else (a test reads the window's source to check it is written only after that yes). It opens no network connection or web address (a test reads its source for this); the commands behind its buttons can, as they always could: on Updates (a look at which releases exist, and fetching one) and on Check the tool (the buttons that mend or build fresh, which can download again), each only after the command has said what it will contact and the person has said yes to a Yes or No question. Hear the voice, Backup and Problem report contact nothing. Backups and reports are written by the commands after their own question, not by the window, and no page reads or runs anything on a timer. It looks like ACK's phone app by default (dark, with cut corners); a switch in the window hands every colour back to the system, including a high-contrast theme. `--check` says why it cannot start. `--install-launcher` puts the window in the menu, after showing exactly what it will write and asking. On a Linux desktop it writes two small files, a menu entry and its icon, under `~/.local/share`. On WSL, whose Start menu is made from system folders that only an administrator can write to, it makes one shortcut in the person's **own Windows Start menu folder** and one small icon file under their Windows application data (`ack-voice-studio`), through `powershell.exe`, which WSL lets Linux start: no `sudo`, no password and no administrator rights. It runs three fixed commands (look, make, remove) passed on the command line as an encoded command; it changes no execution policy, writes no script file, uses no network and starts no other program, and a test reads the commands for all of that. If an organisation's policy blocks Windows programs from WSL, or blocks COM objects in PowerShell, the tool says it cannot reach the Start menu and prints the older steps instead (two `sudo` commands for the person to run themselves; the tool never runs `sudo`). `--remove-launcher` removes only a shortcut, an icon and files that carry this tool's own marker; one of the same name that someone else made is left alone. Nothing starts at login and nothing runs in the background when the window is closed.
* **The one exception, optional and separate:** *Freeform Studio*, the web tool for recording and reviewing in a browser, listens on `127.0.0.1` port 8001 by default (this
  computer only). Its helper script `start.sh` starts it on **`0.0.0.0` (the local network)**, over HTTPS when a certificate is provided and with a private token, so that a phone's browser can record. Voice Studio
  does not start it, and the ACK phone app records without any network. If your policy forbids a listening service, simply do not approve that use.

## 9. Data handling

* Recordings, transcripts, edits, training data and the trained voice **stay on devices the person controls.** Nothing is uploaded, and there is no account.
* The ACK phone app has **no network permission** and its cloud backup is switched off; recordings leave it only when the person saves a file with the system file picker.
* The data folder is in the Linux home directory (under WSL, inside the Linux disk image), not in a OneDrive or other synchronised Windows folder. Back it up the way you
  back up any user data; the tool never deletes a recording by itself.
* **A problem report is a copy of facts about the computer, and of a log if asked.** `python3 -m voice_studio.report` (section 7) blanks names and folders and holds no recordings or phrases, but it is still about this computer, so it is shown in full before anything is written, saved only to a file the person names after a typed yes, and never sent by the tool. A log in it may contain words from recordings; that part is off unless asked for.
* **A backup is a copy of personal data.** `python3 -m voice_studio.backup` (section 7) writes the recordings and notes of one project into a file that is **not encrypted**. Where that file goes matters as much as the recordings: the tool refuses a folder inside a project, says when a folder looks synchronised (OneDrive, or Documents on Windows) and that a copy on the same drive protects against a mistake and not against a failing drive, and never sends a backup anywhere. Choosing a folder that is backed up by the organisation's own means is the administrator's decision, not the tool's.

## 12. Removing it

`python3 -m voice_studio.uninstall remove` takes the programs the tool built and the files it downloaded off the disk and nothing else (section 7); the person then removes the tool's own folder and the menu entry with the commands it prints. To remove everything by hand instead, delete `~/ack-voice-studio/` (the recordings in `projects/` are the person's own: **copy them out first**) and `~/.cache/pip`. The Ubuntu packages in section 4 are ordinary
packages and can be removed with `apt`. Nothing else is installed. The tool's own `backups/` folder is inside `~/ack-voice-studio/`, so a backup kept there is deleted with it: copy it out first, or keep backups in a folder of your own choosing (`--to`).

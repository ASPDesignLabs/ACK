# Changelog

All notable changes to ACK are logged here. These same notes are available in-app from the TERMINAL view — type `/info` and send it.

## [Unreleased]

### Added
- **The voice list now shows voices in every language, with their language named, and SPEECH LANGUAGE chooses the language of a profile that has no voice of its own.** The list in AUDIO ARCHITECT (BASE VOICE) used to keep English voices only. It now lists every language, sorted by language and then by name, with the language written out ("German (Germany)") under each voice, and a note under the list. **Voices that need the internet or are not installed are no longer listed** (ACK has no network permission and promises local-only speech; such a voice would fail silently or send text to a server through the speech engine). This also hides English voices of those two kinds, so a profile that already chose one keeps it chosen; only the picker stopped listing it. **SPEECH LANGUAGE** (AUDIO ARCHITECT) is THIS PHONE'S LANGUAGE or ENGLISH (US) and only affects a profile with no voice chosen: **a new install is given THIS PHONE'S LANGUAGE, an install that already existed stays on ENGLISH (US)** (a German phone that has always spoken English phrases does not start reading them with a German accent), and DELETE DATA > SETTINGS puts the new-install default back and says so. If the speech engine does not have the language it uses its own default and the log says so once a minute at most: a missing language never means silence. A change counts from the next message. **A related fix:** the speech engine keeps the last voice a profile chose, so a profile with no voice used to inherit it; it now asks the engine for the SPEECH LANGUAGE again after a profile has set a voice. The cloned MY VOICE is unchanged. The setting is in EXPORT .JSON (a backup that says nothing leaves your own choice alone; an unknown value is refused with a specific log line). Built and tested without a phone: the choosing, sorting, fallback and backup rules are covered by automated tests, but the voice list on a real engine, a non-English voice speaking, and an English profile staying unchanged were never run on a device (docs/LANGUAGE_VOCABULARY_DEVICE_TEST.md, section I).
- **Word suggestions in the Statement Composer, off until you turn them on.** Under the text box ACK can offer the rest of the word you are typing, or the word that usually comes next, as buttons (the same quiet row as the history chips: 14 sp text, 48 dp buttons, no animation, no sound, no vibration, and the same height whether or not it holds anything, so nothing moves). **Nothing is added until you tap one**; it never corrects or completes by itself. It starts empty and learns only from statements you SAVE, SPEAK or COPY in the composer (the same text counts once), never from the Emergency deck, the Terminal, Manual Override, the Matrix and Quick Actions editors, tags or numbers. Names you already keep in Target Computer (entry names only, never phone numbers, addresses or emails) and Shared Root Variables are offered too, read live and never copied into the learned words. It is off for everyone, new installs included: the composer shows one dismissible box (TURN ON or NOT NOW), and SETTINGS → WORD SUGGESTIONS has the switch, which says ON or OFF in words. The words are a private file on the phone, with no network; there are at most 5,000 words and 20,000 pairs. **SETTINGS → WORD SUGGESTIONS → FORGET WORDS** lists every word with how often it was used (REMOVE asks once more) and FORGET ALL WORDS (asks twice, names a backup first); it works with the switch off. **The words are in EXPORT .JSON, and its warning now names them** (a new line: WORDS LEARNED FROM WHAT YOU SAVED, SPOKE OR COPIED); restoring only adds to what the phone has learned, never lowers a count and never removes a word, and a file with broken word data is refused with a specific reason in the log (counts and lengths only, never a word). The on/off switch is not in the file, so a restore never turns learning on. They go with DELETE DATA → MESSAGES AND DECKS, and the backup reminder ignores them, like the typing history. A damaged word file is set aside, never overwritten. Built and tested without a phone: the rules are covered by automated tests, but the screens, the row at large font sizes and the keyboard behaviour were never run on a device (docs/LANGUAGE_VOCABULARY_DEVICE_TEST.md, section H).
- **ACK can warn you before a profile change makes a Matrix gesture say something different.** You learn which gesture says what by repeating it, and a profile can hold a different phrase for the same slot (a slot with no phrase of its own falls back to the DEFAULT profile's), so changing profile could quietly change what a practised gesture says. Now, when you pick a profile in the app's PROFILE menu and any of the deck's gestures (the twelve built-in ones and any custom context slots) would say something different, ACK shows how many and the first few ("GESTURE NAME: old phrase, becomes: new phrase") and asks: STAY (the highlighted button, and what a tap outside or the back button does) or CHANGE PROFILE. If nothing would change, there is no warning at all. Two phrases that differ only by spaces at either end count as the same; any other difference, including capital letters, counts. The dialog is quiet (nothing spoken, no sound, no animation, nothing starts HELP) and has a box, DO NOT SHOW THIS WARNING AGAIN, that flips the same switch as SETTINGS → PROFILES → WARN BEFORE PROFILE CHANGES. **The switch is ON for a new install and OFF for one that already exists**, which is shown one dismissible offer in SETTINGS (it says what it does, starts OFF, and changes nothing unless you tap TURN ON). It is in EXPORT .JSON (a backup that says nothing leaves your own choice alone). **Only the in-app profile menu asks:** the home-screen widget and the watch change profile without asking (they have no screen to ask on), and restoring a backup is already a confirmed action. It is about the Matrix deck only: Quick Actions, Emergency, Emoji and GIF decks have no profiles, so their buttons never move (a test fails if that ever changes). A voice recording bound to a slot is not part of the comparison. Built and tested without a phone: the decision and the wording are covered by automated tests, but the dialog, the switch and the offer were never run on a device.
- **A brand-new install now opens with plain, neutral starter phrases instead of the developer's own wording, plus a small STARTERS Quick Actions deck. An install that already exists is not changed.** The twelve Matrix gestures stay exactly where they are (they are learned by repetition); only the words are new: Yes., Hello., Please say that again., I am using a communication device., Stop., Please wait, I am typing., I need a break., I need some space., No., Thank you., I need help., Nice to meet you. STARTERS is a Quick Actions deck of twelve buttons grouped by what they do (ANSWERS, REPAIR, SOCIAL), so "Hello." and "Sorry." are still one tap away. They are saved as ordinary values you can edit, and ACK's old built-in wording is never edited (a button with no saved value falls back to it, so changing it would have changed what an existing phone's untouched buttons say). A Matrix deck you make later on such a phone starts with the same twelve, and DELETE DATA > MESSAGES AND DECKS (and so DELETE EVERYTHING) saves them again, so a wiped phone does not show the old wording; DELETE DATA > SETTINGS never touches phrases. **FULL RESTORE of an older backup, or one from a phone that did not have the starters, takes back only the starter phrases you never edited** (a backup never records a phrase left at the built-in text, so they would otherwise show where that phone showed its old wording); a phrase you edited, or that the file mentions, is never touched, and the FULL RESTORE confirmation says so. The new `starterPhrasesSeeded` field in the backup records whether a backup's phone had them (older files read as "no"), and is not part of the backup reminder's fingerprint. The wording is a draft for a speech-language pathologist to review: `docs/STARTER_PHRASES.md` shows exactly what is seeded, and a test keeps that page and the app the same. Built and tested without a phone: what is decided is covered by automated tests, but the seed, the wipe, deck creation and the restore were never run on a device.
- **An install that already existed is offered the newer defaults once, in AUDIO ARCHITECT, and nothing changes unless you choose it.** If you are still on the CYBER voice, or your display preset still cuts messages over 5 words, a banner at the top of AUDIO ARCHITECT says new installs now start with the unprocessed voice and full messages on screen, with [REVIEW] and [NOT NOW]. [REVIEW] lists exactly what would change, with one switch per change (all off to begin with), a BACK UP FIRST button (the same file as EXPORT .JSON, and it tells you whether the backup was written) and APPLY. Choosing the voice selects ORGANIC; choosing full messages adds a new FULL TEXT display preset with your current colours and size and makes it active, leaving your own preset as it is. [NOT NOW], or applying, hides the banner for good. It never opens HELP or takes you to another screen.
- **A warning banner appears when "Display over other apps" is off, and Silent Mode now says so when nothing could be shown or spoken.** Without that permission a message is spoken but never shown on screen, and nothing said so. A red banner (DISPLAY PERMISSION IS OFF. MESSAGES ARE SPOKEN BUT NOT SHOWN ON SCREEN.) now sits above the header on every main screen, with an ALLOW button that opens the right Android settings page. It cannot be dismissed, and it clears itself when you come back from Settings with the permission on. If Silent Mode is also on, a message would produce nothing at all: ACK now writes NOTHING WAS SHOWN OR SPOKEN to the TERMINAL log and shows a toast (at most once a minute), and SETTINGS shows a red line next to the SILENT MODE switch. Your Silent Mode choice is never overridden.
- **Emergency decks can ask for confirmation before sending (CONFIRM BEFORE SENDING in EMERGENCY OVERRIDES).** It is off by default, so nothing changes unless you switch it on. With it on, tapping an emergency tile shows its label and the full phrase it will say, in large type, with big SEND and CANCEL buttons; CANCEL, tapping outside, or Back sends nothing. SEND does exactly what a tap did before (the same speaker, volume boost, alert tone and clearing settings). A blank tile never opens the dialog, and the TERMINAL `/e` command, which you type on purpose, is not asked to confirm. The EMERGENCY screen shows CONFIRM in its overrides line when it is on, and EXPORT .JSON and FULL RESTORE keep the setting (a backup made before this existed restores with it off).
- **With ACK WATCH as the output device, the watch now confirms that it is playing a message, and the phone plays it itself if no confirmation arrives. Update the phone and the watch app together.** Before, the phone sent the audio to the watch, stayed quiet because a watch was in reach, and never checked: one lost piece of audio, or a watch app that was not running, meant the message was heard nowhere and nothing said so. Now the watch replies once it is really playing. If no reply comes in time (a few seconds, longer for a longer message), the phone plays the message on its own speaker and the TERMINAL log says WATCH DID NOT CONFIRM: PLAYING ON PHONE; if the watch is out of range it plays on the phone straight away, as before. After three misses in a row the log adds NO CONFIRMATION FROM WATCH (IS THE WATCH APP UPDATED?). A normal confirmed message logs WATCH CONFIRMED PLAYING and how long it took. FORCE SPEAKER still wins over ACK WATCH. **Emergency messages, and their alert tone, always play on the phone** whatever the output device is, so a bystander hears them and no confirmation wait delays them. Known limits: a confirmation that arrives after the phone has given up can mean the message plays on both the phone and the watch, which is better than silence; and a watch app that has not been updated never confirms, so with ACK WATCH selected every message waits out the timeout and then plays on the phone.
- **EXPORT .JSON now says what the file contains, and that it is not protected, before the file picker opens.** The dialog lists what the file can hold (the Emergency info card, people and places with phone numbers and addresses, saved locations, your voice recordings as audio, messages, statements and decks, settings and history), says it is NOT encrypted and has no password so anyone who opens it can read all of it, and says to save it on this phone or your own computer by cable, not in Google Drive, OneDrive or another online folder. CANCEL opens no picker. The Terminal's `/backup` prints the same facts before its `/backup confirm` line. A test fails if a new field is added to the backup without deciding how this warning describes it.
- **A failed export now says so, and leaves no half-made file.** EXPORT .JSON used to swallow every error, and a null output stream wrote nothing and said nothing. Both it and `/backup confirm` now use one export routine: a toast and a Terminal line say BACKUP EXPORTED, or BACKUP FAILED: ... NOTHING WAS SAVED., and a failed write deletes the file the picker had just created.
- **DELETE DATA in DATA PORT.** A list of twelve areas (messages and decks, the Emergency info card, people and places, saved locations, the Terminal log, message recordings, training data, the trained voice, the GIF library, safety copies, temporary files, and settings), each with what it holds and how much is stored, and DELETE EVERYTHING. Every delete asks twice, with CANCEL as the safe choice, says how to save the data first (BACK UP FIRST opens the EXPORT .JSON warning where that export covers it; for training recordings, the trained voice and the GIF library it names the backup that does), and says it does not touch files you saved elsewhere. SAVED LOCATIONS switches location alerts off first and waits for Google to confirm its geofences are gone, and leaves your zones alone if that cannot be confirmed in Google mode. PEOPLE AND PLACES also sends the paired watch empty lists (a watch out of reach keeps its names until it next connects). SETTINGS and EVERYTHING put the new-install defaults back. A delete that needs it restarts ACK; one that fails lists the areas by name and does not. A test fails if the app starts storing data in a place DELETE DATA does not know about.
- **DELETE CUSTOM VOICE in AUDIO ARCHITECT.** Two confirmations (the first offers EXPORT VOICE BACKUP FIRST and lists the voices that will switch to a normal one). It removes the model, its settings file and the generated token file, moves MY VOICE to ORGANIC and turns USE MY VOICE off on custom slots, and needs no restart. A note under EXPORT VOICE BACKUP says the backup is as private as a recording of you.
- **SAFETY COPIES in DATA PORT.** Before the one-time Target Computer data upgrade ACK writes a private full backup (recordings and Emergency card included, not encrypted) that nothing ever mentioned. It is now listed, only when one exists, and can be deleted: two confirmations, and if you have not exported since it was made the first offers EXPORT FIRST and its button reads DELETE ANYWAY.
- **A quiet backup reminder.** If seven days have passed since your last export (or since ACK first ran, if there has never been one) and settings or decks have changed since, ACK says so: a banner on the TERMINAL and SETTINGS screens only (never on a deck or the Emergency screen), and a small save icon in the header, left of HELP, that opens the same reminder from any screen. BACK UP NOW starts the EXPORT .JSON flow; NOT NOW hides it for 24 hours. BACKUP REMINDER: ON / OFF in DATA PORT switches it. It is checked once when ACK starts, never makes a file for you, appears without any sound, vibration or animation (its buttons give the app's usual tap feedback, like every other button), and adds no notification or permission. By design, switching decks or profiles, sending messages and typing into variable fields are not counted as a change (the device checklist confirms it). Restoring a backup does not count as making one.
- **RECORD FREE SPEECH now says it records anyone nearby.** One line on the RECORD TRAINING DATA screen and a paragraph on the free-speech setup screen before START QUIET CHECK (FREE SPEECH RECORDS EVERYTHING THE MICROPHONE HEARS, INCLUDING ANYONE NEARBY, FOR UP TO 90 MINUTES. TELL THEM FIRST, OR RECORD SOMEWHERE ELSE.), and the HELP step says so too. Script recording is unchanged, and the screen still makes no sound or vibration.
- **Documents.** `docs/PERMISSIONS.md` lists every permission the phone and watch apps declare and why (two look unused or unrequested and are reported, not changed), `docs/DATA_SOVEREIGNTY.md` now covers the phone side and a new section on whether the watch link can pass through Google's servers (Google's documentation says it can; not yet tested on a device), and `docs/PRIVACY_DEVICE_TEST.md` is the on-device checklist.

It takes effect at once with no restart, and only what things are *called* changes: the stored names, deck ids, tags and what a button does are untouched, and HELP shows the name you see. The switch itself is worded the same in both modes so it can always be found. It is in EXPORT .JSON (named in the warning; a backup that says nothing leaves your own choice alone). ### Changed
- **Every insert button now behaves the same way.** The Statement Composer, the Terminal's `/v` and `/t`, Manual Override (`/m`), and the Matrix and Quick Actions phrase editors all insert through one rule: the word or tag goes at your cursor (replacing what is selected), never splits a `[COMPUTER:...]` or `{VAR}` tag or an emoji (a cursor inside a tag inserts after it; a selection touching a tag covers all of it), and a space is added only where one is needed: none after an opening bracket or quote, none before a full stop or a comma, never a double space. What each button inserts is unchanged (a live tag from the chips and the variable picker; the plain label from BROWSE TARGETS; the resolved value in the Terminal). Three visible changes: **Manual Override now adds a space after an inserted word** (it added none); the Composer and Terminal no longer leave a double space before existing text or glue a word onto the one before it; and **the Matrix and Quick Actions editors' `+ VAR`, `+ A/B/C` and INSERT TARGET TAG buttons insert at the cursor instead of always at the end** (a freshly opened editor starts with the cursor at the end, so its first insertion lands last as before). Those editors keep each tag's value by position, so inserting in the middle shifts the values to match and nothing you typed for another tag moves to the wrong tag. A test fails if any screen goes back to splicing text into a field itself. Built and tested without a phone: the rule and the value-shifting are covered by automated tests, the screens were never run.
- **The history chips under variable fields narrow as you type, are larger, and no longer move the screen.** Before, they showed the same five values whatever you had typed, in 9 sp text cut off at 120 dp, and the whole row vanished when empty so everything below it jumped. Now, with nothing typed they show your five most-used values as before; once you type, only values that start with what you typed remain (ignoring capitals, and treating a letter plus a separate accent the same as the single accented letter), and a value you have typed exactly is not offered back. "Mum" and "mum" now count as one word and the most recently typed form is shown (older duplicates already stored are left as they are). Each chip is 14 sp, at least 48 dp tall, up to two lines, and a long value scrolls sideways; one too long to show is shortened in the middle so you can still see how it ends and tell two long values apart. The row keeps a 56 dp height with or without chips, so nothing below it moves; it adds a blank band under every variable field, which is the price of that (you chose it over hiding an empty row). Tapping a chip still replaces the whole field. No animation, no vibration. Known: once a field remembers twenty values each used twice or more, a value typed for the first time is dropped as soon as it is recorded (the cap has always ranked by use count first).
- **New installs show every message in full on screen, shrinking the text to fit, and speak in the unprocessed ORGANIC voice. Existing installs keep their current settings.** A new install starts with a FULL TEXT display preset and the ORGANIC voice; nothing already stored on a phone is changed. On an existing install the older behaviour stays until its owner changes it: a message of more than 5 words is cut to ALERT: plus 3 words. That setting is now called SHOW FULL MESSAGE (VISUAL EDITOR), says what ON and OFF do, and shows THE SCREEN MAY SHOW LESS THAN WAS SPOKEN while it is OFF.
- **The text on the full-screen display now shrinks to fit.** The size in the visual editor is now the largest the text may be (LARGEST SIZE); a long message is shrunk, a step at a time, to the smallest readable size so it is not cut off. If it still does not fit at that size it scrolls, with SCROLL FOR MORE shown, and a tap (or, for an Emergency message, a hold) still clears it. A message that already fit looks as it did. This applies to existing installs too.
- **If the active custom voice is deleted, or a voice id is unknown, ACK now falls back to ORGANIC instead of CYBER.** A broken or deleted voice no longer turns into the robot voice. CYBER is still there to choose, and an install that never chose a voice still speaks as CYBER.
- **Emergency messages now always speak without voice effects, whatever voice is selected.** An emergency message used the active voice, so with CYBER (or MECH, or a custom slot with effects) it came out robotic or pitch-shifted, exactly when a bystander most needs to understand it. Now pitch and speed are normal and the robotic overlay and bitcrush are off for an emergency message (Emergency decks and the TERMINAL `/e` command). The voice's base system voice is kept, and Master Gain and EMERGENCY VOLUME BOOST still apply. Other messages are unchanged.
- **Global Cadence is retired.** It made each word of a message speed up or slow down at random, so the same message sounded different every time, and it broke on messages containing & or <. The GLOBAL CADENCE slider is gone from AUDIO ARCHITECT and ACK now always speaks the plain message (so a custom voice never receives speech markup either). Master Gain, voice profiles and Guide Vox are unchanged. If you had raised Cadence, your stored value is kept (not deleted, and still carried in EXPORT .JSON so older and newer backup files both restore) but is no longer used.
- **The old, unused setup screen was removed.** It could not be reached from anywhere and still carried an earlier app name.
- **COPY in the statement composer, and the copy buttons on contact cards, are unchanged and deliberately do not mark the text as sensitive.** What you copy shows in the phone's clipboard preview so you can check it, and stays plain on the clipboard (a keyboard's clipboard history may keep it). ACK does not clear it afterwards.

### Fixed
- **The confirmation before clearing a phrase's variables (or its prompt) now shows the whole question.** Its text was written as two lines with nothing joining them, so only the second line appeared (for example just "The prompt will remain." without "Clear every local variable value for this phrase?"). All three versions (clear variables, clear prompt, clear both) now show both sentences, worded as before. A test now fails on any two lines of text left unjoined. Built and tested without a phone: the wording is checked by reading the source, the dialog itself was never run.

## [1.0-beta.8] - 2026-10-03

### Added
- **Speak in a voice trained from your own recordings, entirely on the phone.** IMPORT CUSTOM VOICE in AUDIO ARCHITECT takes the voice's two files together (`.onnx` and `.onnx.json`), checks and installs them, and restarts ACK once so every screen sees the new voice. It runs on-device through sherpa-onnx -- no network, no cloud service. One custom voice is installed at a time; importing another replaces it. A voice exported straight from the Piper trainer needs `tools/patch_voice_for_sherpa_onnx.py` run on it first (it keeps a `.before-patch` copy and explains mistakes in plain words); `docs/VOICE_TRAINING_GUIDE.md` covers the whole path.
- **Two ways to put the custom voice on output.** A MY VOICE chip appears in the VOICE PROFILE row once a voice is installed -- one tap and every prompt uses it. Or switch on USE MY VOICE in any custom slot's DSP chain editor for a separately named slot. Master Gain applies, like a recording; ROBOTIC OVERLAY and BITCRUSH don't (the editor hides them with USE MY VOICE on, and the MY VOICE preset says THIS ENGINE HAS NO DSP CONTROLS OF ITS OWN), and pitch and speed have no effect on this voice.
- **The custom voice never leaves you silent.** If it fails to generate an utterance, ACK speaks that one with the phone's normal voice instead. Shake-to-kill stops a custom-voice utterance the same way it stops any other.
- **EXPORT VOICE BACKUP / IMPORT VOICE BACKUP in AUDIO ARCHITECT.** A trained voice is tens of megabytes, so it gets its own standalone `.zip` (the same idea as the GIF deck backup) instead of going inside EXPORT .JSON. Restoring one restarts ACK once.
- **Record your own voice-training data on the phone, away from your computer.** RECORD TRAINING DATA (AUDIO ARCHITECT → CUSTOM VOICE) turns the phone into the recording half of voice training. Write or paste a script and ACK splits it into cards sized to read in one go (about ten seconds each), showing the card count and rough minutes as you type. Then read hands-free: read a card, ACK hears you finish, keeps that clip and shows the next card, so you never touch the phone between cards. A long script can be read over several sessions; each one starts at the first card not yet recorded. Editing or deleting a script asks first.
- **A quiet check, and recording tuned for voice training.** Before each session a two-second quiet check tells you whether the room is loud, the microphone is covered, or something interrupted it. Audio is written straight to the phone's storage as it arrives, at 48 kHz when the phone allows it (otherwise 44.1 kHz), 16-bit mono, from the microphone source with no phone-side processing where the phone offers one. The end-of-card wait (how long a pause counts as "finished") is adjustable from 0.8 to 2.5 seconds, REDO LAST sets a bad clip aside and shows that card again, PAUSE stops listening, and marks (NOISE, UNCLEAR, LAUGH, COUGH, STUMBLE) flag a clip for the review stage on your computer.
- **Free speech, and safeguards while the microphone is open.** RECORD FREE SPEECH keeps up to 90 minutes in one recording, whole; the phone only suggests cut points and never cuts the raw audio. While recording, ACK makes no sound or vibration (a button thump or buzz would land in the recording), locks the screen's orientation, keeps the screen on, and pauses if you leave the app. It needs 300 MB free to start, and pauses (script) or stops and keeps what it has (free speech) before the last 100 MB. If ACK closes in the middle of a card, the unfinished recording is repaired the next time you open RECORD TRAINING DATA and held back until you have listened to it and chosen to keep it.
- **Listen, mark, and save to a file you choose.** Each session's clips can be played through ACK's normal audio output, kept or set aside, and marked. A kept clip has no delete button, and deleting a whole session asks twice. SAVE ALL TO A FILE (or a single session's own SAVE TO A FILE) writes a package -- one `.zip` -- through Android's own save screen, then reads it back and checks every recording in it; if the check fails, the half-made file is deleted and you are told nothing was lost. There is no share sheet and no network: you move the file to your computer yourself. ACK never deletes a session because you saved it.
- **Training scripts are included in EXPORT .JSON and FULL RESTORE FROM JSON.** Only the scripts (text): restore adds or updates by id and never removes anything. Recordings are far larger, so they travel as the packages above, not inside the JSON.
- **A RECORD TRAINING DATA walkthrough in HELP** (BASICS // PERSONALIZATION), and a small dismissible first-use tip on the screen itself. The tip only points you at HELP; it never launches anything for you.
- **New, and still being proven on real phones.** Everything that decides what is recorded, cut, kept and written is covered by automated tests, and the packages ACK writes are opened by the same reader Freeform Studio uses. But it was built and tested without a phone attached, so the microphone, the screens and the file picker are its least-proven parts. `docs/TRAINING_CAPTURE_DEVICE_TEST.md` is a do-this-expect-that checklist for trying it on your phone. If your phone behaves differently, the `ACK_TRAIN` lines in logcat carry counts, sample rates and reasons only -- never audio and never what a script says.
- **The TYPE tab is now the STATEMENT COMPOSER.** Build longer, structured statements out of Target Computer entries and Shared Root Variables -- multi-sentence, not just a single phrase -- with a live preview showing exactly what it'll say before you commit to anything. SAVE keeps the statement's references live rather than freezing their current values, so a saved statement automatically reflects any later change to the entries or variables it points at. COPY places the fully-resolved text on the clipboard (for pasting into Messages, chat apps, or anywhere else); SPEAK sends it straight to output. Tapping a Target Computer chip inserts a live reference to that category's currently-active entry; browsing for a specific entry via BROWSE TARGETS inserts it as plain text instead, since a browsed (not-necessarily-active) pick can't be represented as a live reference. Long-press a chip to change which entry is active for that category -- a real, app-wide change, the same as doing it from the Target Computer tab itself. Included in EXPORT .JSON backups.
- **Copy a composed statement to the clipboard and use it in any other app.** COPY works out every reference at the moment you press it and puts the finished text on the clipboard, ready to paste into Messages, a chat app, an email or anything else -- so a statement built in ACK can also go out as ordinary text. Each saved statement in MY STATEMENTS has the same COPY.
- **MY STATEMENTS organizes saved statements into folders, tree > leaf -- the same organizational shape as Target Computer entries.** Create nested folders, save a statement into any of them (or move one later by resaving it into a different folder), and browse the whole tree with expand/collapse. Reload, copy, speak, or delete a statement right from the list; deleting a folder asks first since it takes everything inside it with it.
- **FULL SCREEN in the statement composer.** A toggle, pinned at the top so it's always reachable, that hides ACK's header and bottom navigation while composing -- more room for longer statements. Automatically turns off if you switch away from TYPE.
- **Classic Manual Override moved to `/m` in the TERMINAL.** With TYPE now the statement composer, the original quick type-and-speak screen (MEMORY BANKS, saved phrases, direct text output) is still there, unchanged -- type `/m` at the TERMINAL prompt and send it to open it.
- **A STATEMENT COMPOSER category in HELP.** An 11-step walkthrough of variable context, building a statement, live versus browsed Target Computer insertion, the live preview, and SAVE / COPY / SPEAK / MY STATEMENTS. The MANUAL OVERRIDE walkthrough now starts from `/m`.
- **SHARE in the GIF deck.** A SHARE button next to DISPLAY FULL SCREEN sends the GIF itself through Android's share sheet (Messages, chat apps, social media). It uses a narrowly scoped file provider that exposes only the GIF library and gives the app you pick temporary read access to the one file. No new permission, and ACK still has no network permission -- the file goes to the app you choose, never anywhere ACK sends it itself.
- **The watch's Target Computer copy is re-synced after every pick or clear,** from any screen, instead of when a deck is activated. The synced data now also carries each category's active entry.
- **ACK Wear relays Target Computer to OVERSEER.** Both the deck-scoped list and a new all-categories list (for OVERSEER's ALL TARGETS browser) are passed on, and a pick made on OVERSEER is passed back to the phone through the existing pick request. Additive: the watch flyout and the legacy 8-slot target picker are unchanged.
- **Freeform Studio and the voice-training guides (desktop tools in this repository, not part of the app).** Freeform Studio runs on your own computer. It takes recordings -- from your phone's browser, or from RECORD TRAINING DATA's packages -- has your computer transcribe them with word timings, lets you review and cut them into training clips (waveform cut points, split, join, spoken forms, reference-text matching), exports approved clips into `piper-recording-studio`'s folders, and builds a Piper training dataset. Backups with checksums, a disk-space guard, a repair command and `install.sh` / `start.sh` are included. To install: clone the repository, run `tools/freeform_studio/install.sh`, and fetch the speech model once; `tools/freeform_studio/README.md` has the exact commands. It never goes online: the speech model loads from your computer only, `python -m freeform_studio.models fetch` is the one command allowed to use the internet and asks first, and a test runs the whole workflow with no network and fails on any outside connection. Guides: `docs/VOICE_TRAINING_GUIDE.md`, `docs/VOICE_DATA_WSL_GUIDE.md`, `docs/DATA_SOVEREIGNTY.md`.
- **Bring RECORD TRAINING DATA's packages into Freeform Studio.** On the Review page use **Add recordings from ACK**, or run `python -m freeform_studio.ack_import <file>.zip` (add `--dry-run` to look first and write nothing). A package that fails any check changes nothing and says why in plain words. Each session becomes one recording; each script card's words become its reference text; the phone's clip boundaries are kept as cuts; and your computer listens again and adds warnings for you to review (no speech, distorted, very quiet, background noise, speech touching the edge, differs from the card, phone and computer disagree). Marks you set on the phone as noise, unclear, laugh or cough keep a piece out of training until you clear them. Importing only adds and is safe to repeat. The package format is written down in `docs/ACK_TRAINING_CAPTURE_FORMAT.md`, and the phone and the computer are tested against the same shared test cases.

### Changed
- **Freeform Studio's install command now clones the default branch.** It used to name a feature branch, which does not carry newer features such as the ACK package importer. If you cloned from a feature branch earlier, move that folder aside and clone again: the folder holds only the program, so your recordings, access token, backups and `~/freeform-studio-venv` are not touched.
- **ACK's data is no longer included in Android's Google cloud backup.** It holds your phrases, recordings, a trained voice, saved places and settings, so none of it is uploaded, whatever the phone's backup switch says. Direct phone-to-phone transfer during setup is still allowed (it doesn't go through the cloud). Restoring a new phone from a Google backup no longer brings ACK's data back -- use EXPORT .JSON and the GIF and voice `.zip` backups, which stay under your control. Checked by `tools/freeform_studio/tests/test_sovereignty_policy.py`, which also fails if ACK ever requests a network permission or uses a network API.
- **ACK is now explicitly licensed GPL-3.0-or-later.** `LICENSE` is the unmodified FSF text, the copyright line lives in `NOTICE`, every source file carries an `SPDX-License-Identifier` line, and `THIRD_PARTY_NOTICES.md` lists every outside component with its license and how that was checked, including the open questions not yet settled.

### Added
- **Autocomplete for variable and Shared Root Variable fields.** ACK now remembers what you've typed into a Matrix node's local variable fields, a Quick Actions slot's local variable fields, and Shared Root Variables' A/B/C values, and offers your most-used past entries back as tappable chips right under the field -- tap one to fill the field with it. Matrix and Quick Actions history is scoped to the exact field it came from; Shared Root Variables history is scoped globally per category, matching how those values already work today. Included in EXPORT .JSON backups.
- **MANAGE AUTOCOMPLETE in PROTOCOL.** A new drill-down browser (Matrix as Deck > Profile > Pose > Node > Variable, Quick Actions as Deck > Group > Slot > Variable, Shared Root Variables as Category > Tag) lists every remembered value by the exact field it belongs to -- same tree style as MANAGE RECORDINGS. Remove one value, clear a single field's whole history, or clear everything at once, all from the same place.
- **Geo-Protocol, visual prompt presets, output device routing, Terminal/STATUSBOX prefs, shake-to-kill sensitivity, and Shared Root Variables' collapsed state are now included in EXPORT .JSON backups.** A rationalization pass found these six settings areas were silently left out of every backup. Every one of them is now captured, and restorable via the new FULL RESTORE FROM JSON below.
- **FULL RESTORE FROM JSON in PROTOCOL's DATA PORT.** Picks a backup file and applies everything it carries -- decks, DSP settings, root overrides, quick actions, emergency prompts, target computer entries, voice recordings, autocomplete history, Geo-Protocol zones, visual prompt presets, output device routing, Terminal/STATUSBOX prefs, shake-to-kill sensitivity, and Shared Root Variables' collapsed/expanded state -- overwriting a matching entry by its id, or adding it if you don't have one yet. Nothing on your device that the backup doesn't mention is touched or removed; to clear something, use that feature's own dedicated clear/delete action instead. Requires confirming first. The former IMPORT .JSON button is renamed **IMPORT MATRIX AS NEW DECK** to distinguish its narrower "matrix phrases into a brand new deck" behavior from Full Restore's much broader reach.
- **BACKUP in the GIF Deck: EXPORT DECK (.ZIP) / IMPORT DECK (.ZIP).** A GIF deck's images and categorization don't fit in a JSON backup -- this is a standalone .zip export instead, with every GIF as a real file inside real deck/category folders, openable and viewable on any device or OS without ACK installed, plus a manifest.json carrying the ids/ordering/toggles needed to restore it faithfully. Import merges by id -- a category or GIF the archive provides is added or updated, anything already on the device that the archive doesn't mention is left alone -- and recreates the deck itself if it doesn't already exist.
- **A watch-side Target Computer flyout for Quick Actions decks.** A new TARGET tap target appears on the watch face (next to where the SHAKY HANDS indicator sits) whenever the active deck is Quick Actions and has at least one Target Computer category synced to it. Tapping it opens a radial menu -- categories, subcategories, and entries arranged around the ring with the highlighted one's full label shown large in the center -- browsable by rotating the crown or tapping a visible slice directly, with dedicated BACK and NEXT (paging) slices. Double-tap the highlighted entry to confirm your pick; it updates instantly on the phone, no unlock required. The flyout's inactivity timeout is configurable (5-30s) in PROTOCOL > HARDWARE CONFIG, alongside FIRE GRACE WINDOW and WAKE GESTURE WINDOW.
- **Quick Actions phrases can now reference Target Computer entries.** Insert a `[COMPUTER:X]` tag from the Quick Actions slot editor the same way you already could in the Matrix node editor, complete with a fallback value and autocomplete for it. Previously the tag was silently ignored (resolved to an empty string) when a Quick Actions phrase played -- Matrix was the only place it actually worked.

### Removed
- **The optical "OPTICAL SYNC [QR]" scanner and its CAMERA permission.** This was never a real QR reader -- it was a bespoke camera-scanned pixel-grid transfer protocol, paired with a web-side encoder that had already been parked as inactive. The Android-side scanner activity, its CameraX dependency, and the CAMERA permission are gone; its whole-protocol restore logic lives on behind the new FULL RESTORE FROM JSON button above, without the camera.

### Fixed
- Output could go quiet or fail to reach the car's speakers at all when connected to Android Auto. ACK never requested audio focus on any playback path -- fine on a phone with nothing else competing, but Android Auto is strict about the standard Android focus handshake while it's juggling navigation, music, and calls, and an app that never asks has no standing in that negotiation. Every dispatch now briefly requests audio focus before playing (and releases it right after), the same signal every well-behaved Android app sends to say "let this through."
- Double-tapping an entry inside the Target Computer flyout to confirm it could also trigger SHAKY HANDS mode. The flyout's own double-tap gesture and the watch's screen-wide long-press/tap-tap-hold gesture loop were both independently watching the same raw touches; a race between the two meant the screen-wide loop's long-press timer could still fire after the flyout had already closed and consumed the pick, by which point a guard checking "is the flyout still open" was checking state that had already changed. The screen-wide gesture loop is now fully suppressed while the flyout (or the legacy target overlay) is open, instead of only guarding the action it would have taken.

## [1.0-beta.6] - 2026-09-22

### Added
- **Pick which device ACK's audio goes to.** A new OUTPUT DEVICE section in PROTOCOL, right below FORCE SPEAKER, lists your currently-connected Bluetooth devices plus ACK WATCH -- tap one to route every spoken prompt there instead of leaving it to whatever the phone's system audio route happens to be. No OS-level settings involved: this only ever reads which devices are already connected, never touches anything outside ACK. FORCE SPEAKER always overrides whatever's picked here. If your selected device disconnects, ACK falls back to the phone's normal output rather than going silent.
- **ACK WATCH as an output device.** Selecting it relays the fully-processed prompt (already gain-adjusted, already effects-applied) to the paired ACK Wear app for playback right there, using the same WATCH AUDIO FEEDBACK volume already in PROTOCOL. Falls back to the phone automatically if the watch isn't reachable when a prompt fires.

### Fixed
- Recorded voice prompts didn't consistently follow AUDIO ARCHITECT's Master Gain the way synthesized speech does. Master Gain was always being applied correctly — the real problem was that a raw recording's starting loudness depends entirely on how loud you spoke and how close to the mic you were, so multiplying two different recordings by the same gain produced two different results. Every recording is now loudness-normalized to a consistent baseline (right after noise reduction and silence trimming, alongside the existing processing step), so Master Gain multiplies from the same starting point every time — the same way it already does for synthesized speech. Existing recordings are normalized automatically, once, the next time you open the app.
- Every spoken prompt — synthesized or recorded, Emergency included — now always nudges the device's media volume up to an audible floor before it plays, rather than only doing so once Master Gain was boosted above a threshold. Output could previously go quiet if something outside ACK (a Bluetooth headset's own volume control, the notification volume rocker, anything else touching the same volume stream) had turned system volume down since the last time that threshold was crossed. This never lowers volume you've deliberately set high — only raises a stream that's sitting below the floor.

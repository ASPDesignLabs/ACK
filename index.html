Non-traditional AAC

Communicate without needing to speak — or even touch your phone.

ACK is a heavily modified take on augmentative and alternative communication (AAC), built around gesture recognition instead of the grid-of-buttons approach most AAC tools default to. Compose statements, build context-based replies, and fire them off with a tap — or with a three-pose gesture from your wrist, hands-free, even with your phone locked in your pocket.

Built by one person, primarily to work around situational mutism — the moments where speaking out loud is much harder than it should be, even though nothing is wrong with the ability to communicate. I am not a speech-language pathologist, a mental health professional, or anyone with formal training in AAC design. This is a tool I built for myself that I'm sharing because it might help someone else too — not a clinical recommendation.

Heads up: this is a solo, daily-driven work in progress. Expect bugs, expect things to move around between updates, and expect the roadmap below to be honest about what's unfinished.

How it works

Three ways in, one output.

Tap controls

The baseline. Every deck and prompt works from direct touch input on the phone — no watch, no gesture setup required to get started.

Gesture playback

A companion Wear OS app reads a three-pose gesture system — ARM → LOCK POSE → MODIFY → FIRE — letting you trigger prompts entirely touch-free, even with the phone locked and in a pocket.

Full-screen output

Prompts play back full-screen with visual and audible output together, with audio routing to either the phone speaker or a connected Bluetooth speaker.

Decks

Everything is organized into decks.

A deck groups one style of communicating — routine replies, emergency overrides, emoji reactions, memes — and a profile lets the same deck carry different content for different people or situations without losing your layout. Switching decks changes what you're saying; switching profiles changes who you're saying it to.

Matrix Deck
The core deck type: a node-based grid of prompts driven by root-level variables, with a live template editor so a single saved phrase can adapt to context. Supports multiple decks at once, each with its own set of profiles.
Quick Actions Deck
Three pose groups, four fixed actions each — the fastest path from gesture to output when you don't need to compose anything, just fire a known phrase.
Emergency Deck
High-priority prompts that override whatever else is currently playing, with a fast clear so the display doesn't get stuck mid-message during something urgent.
Emoji Deck
Visual, emoji-first prompts for quick emotional context — configure a tile, pull from a library, or pair it with related panels for a fuller reaction.
GIF Deck
Local GIF import and playback, organized into categories, in a landscape-friendly display — for anyone who genuinely communicates through memes and wants to bring that outside a chat window.
Manual Override
Memory banks and saved phrases with direct keyboard text output — the fallback for whenever gesture input isn't available or isn't convenient in the moment.
Target Computer
Configurable target slots that prepend or append text and route a finished message somewhere specific — think of it as addressed, reusable message shells rather than typing the same lead-in every time.

Making it sound like you

Composable statements, tuned to your voice.

Statements aren't limited to fixed phrases. ACK's template engine supports one-off statements, routine replies, and composable, bridged statements — building a full reply out of smaller context-based pieces instead of writing every combination out by hand.

Audio Architect

Mild-but-real adjustments to the built-in TTS voice: base voice selection, pitch and speed, an optional robotic overlay or bitcrush texture, and custom profile slots so more than one tuned voice can be saved and switched between. Output routing and gain live here too. None of it aims to be a perfect voice clone — just enough tone, speed, and cadence control to make the default a little more "you."

Location awareness

Geo-Protocol: context that follows where you are.

Geo-Protocol lets specific zones change what's available or how decks behave when you enter or leave them — so the same gesture can mean something slightly different at home versus somewhere unfamiliar.

This runs entirely on-device. ACK's Android manifest requests no INTERNET permission anywhere in the app — location data isn't sent anywhere, because there's no network path for it to travel on in the first place.

Training & confidence-building

Practice the gestures before you need them.

Training Ground

Free-form gesture practice with live telemetry and normal pacing — nothing you do here actually plays back or sends output. A safe space to get the arm/lock/modify/fire cycle into muscle memory.

Deck Trainer

Scored practice against your own real Matrix or Quick Actions deck, so you're rehearsing the actual layout you'll use — not a generic demo.

The companion

A Wear OS app that does the physical half.

The watch side is deliberately small: it's what senses the pose, watches for a wake gesture (by default, a triple wrist twist so commands can't fire by accident), and pushes that event to the phone. The phone stays in charge of decks, profiles, and playback. A background sensor service on the watch keeps this working without needing the watch screen to stay open the entire time you're wearing it.

Help, onboarding & transparency

A tutorial system that only advances when you actually do the thing.

ACK's in-app help isn't a slideshow. Each module only steps forward when a real event fires from the real UI — a specific tap, a committed text field, a cleared overlay, an actual watch gesture broadcast — so finishing a walkthrough means you've genuinely done it once, not just read about it.

Under the hood

For anyone who wants to build it themselves.

ACK is Kotlin + Jetpack Compose, split into a phone module and a Wear OS module. Maps are rendered fully offline with Mapsforge/vtm — no tile server, no network dependency, matching the rest of the app's local-first design.

Build requirements

  • Android Studio
  • A custom Mapsforge-compatible map splice for your local region, dropped into app/src/main/assets

Full contribution workflow — branch naming, commit conventions, and the day-to-day git flow — is documented in docs/GIT_WORKFLOW.md.

Status & disclaimers

Where this actually stands.

This section gets updated by hand against docs/HELP_TUTORIAL_GUIDE.md — it's a snapshot, not a live feed, so treat it as "true as of the last update," not real-time.

Known gaps

  • Several help/tutorial modules are written but not yet wired to live UI tags (Emergency, Emoji, GIF, Quick Actions decks, Deck Management, and Manual Override rewrites).

Not a substitute for professional AAC evaluation or speech-language therapy. Built by one person as a personal tool, shared as-is.
